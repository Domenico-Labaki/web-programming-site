For this Flask portfolio, test validation rules with unit tests, request handling with Flask's test client, and interactions such as quiz retries and keyboard focus in a real browser. Choose the smallest test that can observe the failure.

What to test

Unit tests for profile rules
Run the validator with valid, invalid, and boundary values. Check that a whitespace-only description is rejected, that graduation months match the selected term, and that invalid student ID lengths produce a field error.
Integration tests for forms and JSON routes
Post invalid data directly to /profile-validated and assert that the form displays field errors. Seed an isolated test database for the quiz and verify that the count endpoint returns JSON, that a known question has the expected fields, and that an out-of-range index returns HTTP 404.
Browser tests for interactions
Complete a quiz using the keyboard and verify that focus moves to the result. Simulate a failed request in the test browser, retry it, and verify that the selected answer is preserved. Check the profile form for inline feedback and keyboard navigation.

When to run the checks

  1. Run unit and integration checks before merging. For a new bug, add a small test that fails before the fix and passes afterward.
  2. Run browser checks for changes to forms, quiz interactions, or navigation. Use repeatable fixtures and keep test data separate from production.
  3. After deployment, smoke-test the public homepage, research hub, and quiz. Record the commit, environment, expected result, and actual result for any failure.

Starting point in this repository

The current suite uses Python's unittest and already checks profile validation boundaries and a direct invalid form submission. Run it locally with the command below. The quiz API and browser checks above describe the proposed coverage for this strategy.

python -m unittest discover -s tests -v
