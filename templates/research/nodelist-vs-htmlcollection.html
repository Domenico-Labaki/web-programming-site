Live collection or snapshot?

Both are array-like DOM collections: they have a length and indexed items, but are not JavaScript arrays. A live collection updates its membership as the DOM changes; a static collection keeps the same membership. [1] [2]

HTMLCollection
Contains elements only and is live. For example, getElementsByTagName() updates when matching elements are added or removed. [2]
NodeList
Can contain different node types, including text nodes. It can be live or static: childNodes is live, while querySelectorAll() returns a static NodeList of matching elements. [1]
{% call research_figure("dom-model.svg", 428, 443, "A DOM tree with document, HTML elements, attributes, and separate text nodes") %} The tree shows elements and text as different kinds of nodes. That distinction explains why childNodes can include text while an HTMLCollection contains elements only. Birger Eriksson via Wikimedia Commons. CC BY-SA 3.0. {% endcall %}

Example

const box = document.createElement('div');
box.innerHTML = '<p>First</p>';
const live = box.getElementsByTagName('p');
const snapshot = box.querySelectorAll('p');
box.appendChild(document.createElement('p'));
console.log(live.length);     // 2: updated
console.log(snapshot.length); // 1: unchanged

Takeaway: Check the API that produced the collection. Use Array.from(collection) when you need array methods or fixed membership while editing the DOM. A snapshot still holds references to the original nodes; it does not freeze their content. [1] [2]
